# CLAUDE.md — working rules for this repository

Guidance for Claude (and any AI assistant) contributing to the **Bitcoin
Developer Sandbox & Starter Kit**. Read this before making changes. When a
request conflicts with these rules, stop and ask.

---

## 1. What this project is

A zero-friction, disposable **Bitcoin Core 31.1 regtest** playground plus a
progressive suite of runnable examples that turn *Mastering Bitcoin (3e)* and
*Mastering the Lightning Network* theory into executable code. Audience:
developers learning Bitcoin protocol engineering and preparing to contribute to
Bitcoin Core and the wider ecosystem.

The full roadmap lives in `plan.md` (maintainer-local, git-ignored). Treat
`plan.md` §7a **Design Decisions (D1–D7)** as binding — see §4 below.

## 3. Golden rules

1. **No secrets, ever** — but note the RPC credentials in this repo
   (`bitcoinrpc` / `bitcoinrpcpassword`) are **intentionally public** and
   **regtest-only**. Never present them as sensitive; never wire them to
   anything that could reach mainnet.
2. **regtest only.** No code path may connect to mainnet, testnet, or signet.
   No real coins, no real network.
3. **Bitcoin Core 31 is descriptor-wallet only.** Do not use removed legacy RPCs
   (`addmultisigaddress`, `importaddress`, `importprivkey`, `dumpprivkey`,
   `sethdseed`, BDB `createwallet` flags). Build multisig/scripts with the
   example's own crypto library and `importdescriptors` for watch-only.
4. **No runnable Lightning in v1** (D2). The `lnbook` mapping is a reading guide.
   Do not add LND/CLN/Eclair to the toolchain or a `07-lightning` example
   unless the user explicitly re-scopes.
5. **Config comes from `.env`.** No hardcoded ports, URLs, credentials, or wallet
   names in any example or script — read the keys in §6.
6. **Every example is self-sufficient.** It calls the shared bootstrap, funds
   itself, asserts, and cleans up after itself conceptually (regtest is
   disposable; `reset-lab.sh` is the hard reset).
7. **`init-lab.sh` never mines.** The node boots at height 0 so the workshop's
   "fresh node shows `blocks: 0`" story holds. Only the per-example **bootstrap
   helper** mines (101 blocks for coinbase maturity).
8. **Keep the four docs in their lanes** (see §7). Don't duplicate the CLI
   cheatsheet into `README.md` or `docs/cheatsheet.md`.
9. **Book links always point upstream** —
   `https://github.com/bitcoinbook/bitcoinbook/blob/develop/<file>` and
   `https://github.com/lnbook/lnbook/blob/develop/<file>`. Never link a local
   `bitcoinbook/…` path (it 404s on GitHub) and never call the books "submodules".
10. **Never add an AI co-author / `Co-Authored-By` trailer** to commits.

## 5. Example authoring rules (the Language Port Contract)

Every language implementation of an example **MUST**:

1. Read connection settings **only** from `.env` (keys in §6) — no hardcoded
   ports/creds/URLs.
2. Call the shared **bootstrap**: load-or-create the `lab` wallet; if spendable
   balance is 0, `generatetoaddress 101` to a wallet address (coinbase maturity).
   Idempotent — safe to run repeatedly.
3. Print **numbered steps** with `✓` / `✗` markers and a final one-line
   `PASS` / `FAIL` summary.
4. **Exit non-zero** on any failed assertion; exit `0` only on full success.
5. Run from one documented command: `python main.py`, `npm start`, `cargo run`,
   `go run .`.
6. Need **no network** beyond the local regtest node.

### Layout & naming

```
examples/
  <NN-name>/
    README.md            # goal, upstream MB/MLN chapter links, per-language run steps
    python/   main.py
    typescript/ main.ts
    rust/     Cargo.toml  src/main.rs
    go/       go.mod      main.go
```

- Entry file is **`main.*`** in every language dir — no other name.
- Shared code per language lives in the toolchain root:
  `examples/python/common/`, `examples/typescript/src/common/`,
  `examples/rust/…`, `examples/go/…`.
- `NN` is a zero-padded ordinal. `00-cli-workshop/` is prose-only (no `.env`, no
  language dir, not run by `test-examples.sh`).
- **Pin dependency versions** in `requirements.txt` / `package.json` /
  `Cargo.toml` / `go.mod` — the sandbox is meant to be deterministic.
- `scripts/test-examples.sh` auto-discovers `examples/<NN>/<lang>/` with a
  manifest and aggregates exit codes; don't hardcode an example list.

### Library expectations

- **Python**: `requests`, `python-dotenv`, `pyzmq`, `embit`. Not
  `python-bitcoinlib`, not `bit`. Install into a **venv**
  (`python -m venv --copies .venv`) — Debian's system Python is PEP 668
  "externally managed" and rejects a bare `pip install`; `--copies` avoids
  symlink creation, which fails on bind-mounted workspaces (OrbStack / Docker
  Desktop virtiofs).
- **TypeScript**: `bitcoinjs-lib` v6 with `@bitcoinerlab/secp256k1` via
  `initEccLib` for Taproot; `bip39`, `bip32`, `zeromq`.
- **Rust**: `rust-bitcoin` (`bitcoin` crate — `script`, `sighash`, `psbt`) +
  `bitcoincore-rpc` (or `corepc-client`); the sync `zmq` crate for `06`
  (`libzmq3-dev` + `pkg-config` are in the devcontainer — keeps the lab
  framework-free, no async runtime).
- **Go**: `btcsuite/btcd/rpcclient` + `btcd/btcutil` + `btcd/txscript`
  (+ `btcd/btcec` for keys); `pebbe/zmq4` for `06`.

## 6. Environment & config — single source of truth

Change these in **one** place and keep every file in sync (see §8).

| Thing | Value |
| :-- | :-- |
| Bitcoin Core version | **31.1** |
| JSON-RPC / REST | `http://127.0.0.1:18443` (REST under `/rest/`) |
| ZMQ rawblock / rawtx | `tcp://127.0.0.1:28332` / `:28333` |
| P2P | `127.0.0.1:18444` |
| RPC user / password | `bitcoinrpc` / `bitcoinrpcpassword` (public, regtest-only) |
| Wallet name | `lab` |
| Lab data dir | `$HOME/btc-lab` (override with `BTC_DATADIR`) |
| CLI helper | `btc` = `bitcoin-cli -datadir="${BTC_DATADIR:-$HOME/btc-lab}"` |

`.env.example` keys (exact names):

```
BITCOIN_RPC_URL=http://127.0.0.1:18443
BITCOIN_RPC_USER=bitcoinrpc
BITCOIN_RPC_PASSWORD=bitcoinrpcpassword
BITCOIN_RPC_WALLET=lab
BITCOIN_ZMQ_RAWBLOCK=tcp://127.0.0.1:28332
BITCOIN_ZMQ_RAWTX=tcp://127.0.0.1:28333
```

`bitcoin.conf` (written by `init-lab.sh`). Global section: `regtest=1`, `server=1`,
`rest=1`, `txindex=1`, `rpcuser`/`rpcpassword` (plaintext is deliberate —
self-documenting for a throwaway regtest node; clients send it as HTTP Basic auth
from `.env`). **Under `[regtest]`** (Core rejects these in the global section on
regtest): `fallbackfee=0.0002`, `rpcbind=0.0.0.0`, `rpcallowip=0.0.0.0/0` (safe —
node reachable only via localhost port-forwards), `zmqpubrawblock`/`zmqpubrawtx`
on `0.0.0.0`. The heredoc carries a `rev` marker; `init-lab.sh` rewrites any
older layout (old copy saved as `bitcoin.conf.bak`).

**Responsibilities:**
- `init-lab.sh` — write `bitcoin.conf`, generate `.env` from `.env.example`,
  start `bitcoind` at height 0. **Does not mine.**
- Per-example **bootstrap** — wallet + coinbase-maturity mining. Nothing else
  mines automatically.
- `reset-lab.sh` — wipe regtest state back to height 0.

## 8. Consistency invariants — check on every change

When you touch any of these, grep the repo and update **all** occurrences:

- **Core version `31.1`** — `README.md` badge, `.devcontainer/Dockerfile`
  (`ARG BITCOIN_VERSION`), `devcontainer.json` `name`, `plan.md`, docs.
- **Ports `18443` / `28332` / `28333` / `18444`** — `bitcoin.conf`,
  `.env.example`, `devcontainer.json` `forwardPorts`, `.gitpod.yml` `ports`,
  `README.md` endpoint table, docs.
- **RPC creds & wallet name `lab`** — `.env.example`, `bitcoin.conf`, README,
  example bootstrap.
- **Entry filename `main.*`** — every example dir, `test-examples.sh`,
  `docs/adding-a-language.md`.
- **Data dir `$HOME/btc-lab`** — `scripts/*`, Dockerfile `btc` wrapper, docs.
- **License holder / year** — `LICENSE`, `README.md` badge.
- **Book URLs** — `develop` branch, `README.md` + every example `README.md` +
  `plan.md` §3.

## 9. Git & commit conventions

- Branch from `main`; **never commit directly to `main`** (branch protection
  rejects it). Open a PR.
- **Sign every commit** (`git commit -S`, SSH or GPG). Unsigned commits fail the
  branch check — see `CONTRIBUTING.md`.
- **Conventional Commits**: `feat(examples): …`, `fix(scripts): …`,
  `docs(readme): …`, `chore(devcontainer): …`.
- **Do not** add `Co-Authored-By` / "Generated with" AI trailers.
- Commit only tracked-appropriate files. `plan.md`, `.env`, `bitcoinbook/`,
  `lnbook/`, `*.pptx` stay local.
- Commit or push only when the user asks.

- [ ] `bash scripts/init-lab.sh` brings up a clean height-0 node.
- [ ] Affected examples run green: `bash scripts/test-examples.sh` (or the single
      example's one-line command) — exit `0`, `✓` on every step.
- [ ] No hardcoded ports / creds / URLs / wallet names introduced (§5.1).
- [ ] All Markdown links resolve — book links go upstream, internal links exist.
- [ ] Consistency invariants (§8) still hold across every file.
- [ ] New files that match a `.gitignore` glob have a `!negation`.
- [ ] Docs stayed in their lanes (§7).
- [ ] `plan.md` updated if scope, decisions, or the roadmap moved.
