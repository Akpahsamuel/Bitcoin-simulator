# Programmatic Reference: RPC / REST / ZMQ

A quick lookup for calling the sandbox node from code, in each of the four
lab languages. Looking for `bitcoin-cli` commands instead? Those live in
[`examples/00-cli-workshop/README.md`](../examples/00-cli-workshop/README.md).
For *why* these interfaces are shaped this way, see
[`architecture.md`](architecture.md).

All connection details come from the repo-root `.env` (generated by
`scripts/init-lab.sh` from `.env.example`) — never hardcode these:

| Key | Default |
| :--- | :--- |
| `BITCOIN_RPC_URL` | `http://127.0.0.1:18443` |
| `BITCOIN_RPC_USER` | `bitcoinrpc` |
| `BITCOIN_RPC_PASSWORD` | `bitcoinrpcpassword` |
| `BITCOIN_RPC_WALLET` | `lab` |
| `BITCOIN_ZMQ_RAWBLOCK` | `tcp://127.0.0.1:28332` |
| `BITCOIN_ZMQ_RAWTX` | `tcp://127.0.0.1:28333` |

## 1. JSON-RPC

### Raw shape (any language, via `curl`)

```bash
curl -s --user bitcoinrpc:bitcoinrpcpassword \
  --data '{"jsonrpc":"1.0","id":"x","method":"getblockchaininfo","params":[]}' \
  -H 'content-type: application/json' \
  http://127.0.0.1:18443/
```

Wallet-scoped methods (see `architecture.md` §3) target
`/wallet/<name>` instead of `/`:

```bash
curl -s --user bitcoinrpc:bitcoinrpcpassword \
  --data '{"jsonrpc":"1.0","id":"x","method":"getbalance","params":[]}' \
  -H 'content-type: application/json' \
  http://127.0.0.1:18443/wallet/lab
```

### Common methods used across the labs

| Method | Scope | Used in |
| :--- | :--- | :--- |
| `getblockchaininfo` | node | `01` |
| `createwallet` / `loadwallet` | node | bootstrap (all labs) |
| `getnewaddress` | wallet | `01`–`06` |
| `generatetoaddress` | wallet | bootstrap, `05`, `06` |
| `getbalance` / `listunspent` | wallet | `01`, `03`, `04` |
| `createrawtransaction` | node | `03`, `04`, `05` |
| `signrawtransactionwithwallet` | wallet | `03` |
| `getdescriptorinfo` / `importdescriptors` | node / wallet | `04` |
| `testmempoolaccept` | node | `03`, `04`, `05` |
| `sendrawtransaction` | node | `03`, `04`, `05` |

| `validateaddress` | node | `02` |

### Per-language call

Every language reuses the shared `common` client instead of hand-rolling HTTP:

**Python** (`common/rpc.py`)
```python
from common.rpc import BitcoinRPC

node = BitcoinRPC()                    # unscoped: node-level RPCs
wallet = node.for_wallet("lab")        # scoped: wallet RPCs
info = node.call("getblockchaininfo")
balance = wallet.call("getbalance")
chaininfo = node.get_rest("chaininfo.json")
```

**TypeScript** (`src/common/rpc.ts`)
```typescript
import { BitcoinRPC } from "./common/rpc.js";

const node = new BitcoinRPC();
const wallet = new BitcoinRPC({ wallet: "lab" });
const info = await node.call("getblockchaininfo");
const balance = await wallet.call("getbalance");
```

**Rust** (`common/src/rpc.rs`)
```rust
use common::rpc::BitcoinRPC;

let node = BitcoinRPC::new();
let wallet = node.for_wallet("lab");
let info = node.call("getblockchaininfo", vec![])?;
let balance = wallet.call("getbalance", vec![])?;
```

**Go** (`common/rpc.go`)
```go
node := common.NewBitcoinRPC()
wallet := node.ForWallet("lab")
info, err := node.Call("getblockchaininfo")
balance, err := wallet.Call("getbalance")
```

## 2. REST

Unauthenticated `GET` under `/rest/` on the same port, format suffix required
(`.json` is what every lab uses):

| Endpoint | Returns |
| :--- | :--- |
| `/rest/chaininfo.json` | Chain tip, height, difficulty |
| `/rest/tx/<txid>.json` | Decoded transaction |
| `/rest/block/<hash>.json` | Decoded block |
| `/rest/headers/<count>/<hash>.json` | `<count>` block headers starting at `<hash>` |
| `/rest/mempool/contents.json` | Full mempool, keyed by txid |

```bash
curl -s http://127.0.0.1:18443/rest/chaininfo.json
```

In code, use the client's REST getter rather than a raw HTTP call:
`node.get_rest("chaininfo.json")` (Python) / `node.GetREST("chaininfo.json")`
(Go) / the equivalent in TypeScript and Rust — it prefixes the base URL and
`/rest/` for you.

## 3. ZMQ

Two PUB sockets, enabled in this sandbox's `bitcoin.conf` (see
`architecture.md` §5 for why only these two topics are on):

| Topic | Address (`.env` key) |
| :--- | :--- |
| `rawblock` | `BITCOIN_ZMQ_RAWBLOCK` (`tcp://127.0.0.1:28332`) |
| `rawtx` | `BITCOIN_ZMQ_RAWTX` (`tcp://127.0.0.1:28333`) |

Every frame is a 3-part multipart message: `[topic, raw_bytes, sequence_le_u32]`.
**Subscribe before the event happens** — PUB/SUB has no history, so a late
subscriber simply never sees a past notification.

**Python** (`pyzmq`)
```python
import zmq
ctx = zmq.Context()
sub = ctx.socket(zmq.SUB)
sub.setsockopt(zmq.SUBSCRIBE, b"rawtx")
sub.connect(cfg["zmq_rawtx"])
topic, body, seq = sub.recv_multipart()
```

**TypeScript** (`zeromq`)
```typescript
import { Subscriber } from "zeromq";
const sock = new Subscriber();
sock.connect(cfg.zmqRawTx);
sock.subscribe("rawtx");
for await (const [topic, body, seq] of sock) { /* ... */ break; }
```

**Rust** (`zmq` crate)
```rust
let ctx = zmq::Context::new();
let sub = ctx.socket(zmq::SUB)?;
sub.set_subscribe(b"rawtx")?;
sub.connect(&cfg.zmq_raw_tx)?;
let parts = sub.recv_multipart(0)?; // [topic, body, sequence]
```

**Go** (`pebbe/zmq4`)
```go
sub, _ := zmq4.NewSocket(zmq4.SUB)
sub.SetSubscribe("rawtx")
sub.Connect(cfg.ZMQRawTx)
parts, err := sub.RecvMessageBytes(0) // [topic, body, sequence]
```

Decode the payload against the node to confirm it matches
(`decoderawtransaction` for `rawtx`, `getblock <hash> 0` for `rawblock`) — see
lab [`06-zmq-listener`](../examples/06-zmq-listener/README.md) for the full
subscribe → trigger → verify pattern in all four languages.
